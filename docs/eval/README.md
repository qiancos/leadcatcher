# 评测口径说明

`cases.jsonl` 是这个项目的**尺子**。改 Prompt、改规则、换模型，都必须在这 30 条上跑一遍，
否则"我觉得变好了"没有任何意义。

```bash
cd server
.venv/Scripts/python run_eval.py            # 当前 provider
.venv/Scripts/python run_eval.py --verbose  # 逐条明细 + 摘要失配定位
.venv/Scripts/python run_eval.py --save     # 结果写入 eval_runs 表
```

## 样本构成（30 条）

| 类别 | 条数 | 验什么 |
| --- | --- | --- |
| `normal` | 12 | 主路径：六字段抽取 + 四级判级 |
| `no_phone` | 4 | 缺联系方式、中文数字号码、号码在结尾 |
| `agent_phone` | 3 | **防误取业务员/渠道号码**（本项目最致命的一类错） |
| `invalid` | 5 | 广告、招聘、乱码、问路、同行探价 |
| `duplicate` | 4 | 同号强重复 ×2、相似文本弱重复 ×2 |
| `edge` | 2 | 长文多轮对话、多意图（本人+朋友） |

## 判定口径（写死，不允许临时调松）

| 字段 | 判定方式 | 为什么这么定 |
| --- | --- | --- |
| 手机号 | 精确比对，空对空算对 | 号码没有"差不多对" |
| 意向等级 | 精确比对 | 这是业务唯一真正在意的数 |
| 客户行业 | 精确；标注为 `null` 的样本不参与 | 无标注即无对错，不能拿空对空凑分 |
| 预算 | 标注里的金额必须是预测金额的子集 | 金额错一个数字就是错 |
| 需求摘要 | **关键信息点覆盖率 ≥ 60%**（命中 `keywords` 里 2/3 即通过） | 中文摘要没有唯一答案，字面匹配会误杀改写 |

### 关于需求摘要这个指标（踩过的坑）

第一版用"3-gram 覆盖率 ≥ 0.5"做摘要判定，跑出来只有 36%。逐条看明细才发现：
**不是抽取错了，是尺子错了。** 标注里写的是"希望到店沟通"，原话是"能到店聊吗"，
改写版摘要天然按字面匹配不上——任何抽取器都过不了这一关。

改成"关键信息点覆盖率"（每条样本人工标 2–4 个信息点，如 `["口腔诊所","成都","获客"]`），
分数回到 95%，且失败的那 1 条（长文 C29）是**真的抽不全**，不是被误杀。
指标从"看起来很严格"变成"说得出错在哪"。

### 关于 exclude 规则

- `invalid` 样本不评判需求摘要：替一条广告写摘要没有标准答案
- `低` 意向样本不评判需求摘要：这类线索的摘要本身没有信息量
- 行业标注为 `null` 的样本不参与行业统计

以上三条都写在 `run_eval.py` 里，改口径要改代码并说明原因，不能只在报告里换个分母。
